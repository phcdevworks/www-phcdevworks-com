# Markdown Standards

Markdown files are part of the product surface for this repository. Keep them
small, current, and aligned with PHCDevworks positioning.

## Voice

- company-first
- concise
- technically credible
- direct
- free of filler and inflated claims

## Structure

- use one H1 per document
- keep sections short
- prefer flat lists over nested lists
- use repository-relative links for local docs
- keep command examples copyable

## Required Alignment

When editing docs, check related files for drift:

- `README.md`
- `CONTRIBUTING.md`
- `CHANGELOG.md`
- `SECURITY.md`
- `AGENTS.md`
- `CODEX.md`
- `BRAND.md`

## Common Drift To Fix

- describing the site as only a Spectre website
- listing scripts that no longer exist
- omitting scripts that contributors need
- stale badge links or repository names
- broad marketing language that does not describe actual work
- changelog entries that are too vague to review later
